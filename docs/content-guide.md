# Content Guide

Этот документ нужен для спокойной поддержки сайта без хаотичных правок по компонентам.

## Где что хранить

Контент сайта хранится в `apps/web/lib/content/`.

Структура:

- `types.ts` — типы для сущностей сайта.
- `services.ts` — услуги и тексты по направлениям.
- `specialists.ts` — специалисты и их краткие профили.
- `contacts.ts` — контакты, карты, ссылки на запись.
- `navigation.ts` — навигация сайта.
- `prices.ts` — ценовые группы на будущее и для скрытого/внешнего сценария.
- `media.ts` — реестр брендовых изображений и alt-текстов.
- `index.ts` — единая точка экспорта.

Файл `apps/web/lib/site-content.ts` оставлен как совместимый фасад. Новые данные лучше добавлять в `apps/web/lib/content/`, а не обратно в один большой файл.

## Как обновлять тексты

1. Найти нужный контентный модуль.
2. Изменять только данные, а не JSX-компоненты, если визуальная структура не меняется.
3. После правок прогнать:

```bash
npm run build:web
npm run typecheck:web
```

4. Проверить, что новые тексты не ломают адаптив и не становятся слишком длинными для карточек.

## Медицинские формулировки

На сайте нельзя обещать лечение, исцеление или гарантированный результат.

Не использовать:

- `лечим`
- `вылечиваем`
- `излечиваем`
- `исцеляем`
- `гарантируем выздоровление`
- `избавляем от заболевания`

Предпочитать:

- `работаем с...`
- `помогаем...`
- `поддерживаем...`
- `может способствовать...`
- `подбираем подход...`

Если есть сомнение, выбирать более нейтральную формулировку.

## Как работать с фотографиями

Исходники лучше хранить отдельно от репозитория: в облачной папке владельца проекта.

В репозиторий класть уже подготовленные web-версии.

Папки:

- `apps/web/public/images/space/`
- `apps/web/public/images/team/`
- `apps/web/public/images/services/`

Правила:

- использовать латиницу и kebab-case в именах файлов;
- не хранить в `public` тяжёлые оригиналы “как с телефона/камеры”;
- у каждого изображения должен быть понятный `alt`;
- перед добавлением фото понять его назначение: `hero`, `space`, `team`, `detail`.

## Как добавлять новые фото

1. Подготовить web-версию изображения.
2. Положить файл в нужную папку внутри `public/images/`.
3. Добавить запись в `apps/web/lib/content/media.ts`.
4. Использовать этот объект в компоненте или странице.

Так не теряются alt-тексты и становится проще потом переезжать в CMS.

## Когда уже нужна CMS

Переход к CMS имеет смысл, когда одновременно выполняются хотя бы 2-3 условия:

- тексты меняются часто;
- фото регулярно обновляются;
- контент должен править не разработчик;
- появляется много специалистов, услуг или SEO-страниц.

До этого этапа текущая файловая структура проще, дешевле и надёжнее.
