# Content Operations Plan

## Цель

Сделать поддержку сайта предсказуемой: чтобы новые тексты, фотографии и карточки специалистов добавлялись без хаотичных правок и без риска сломать интерфейс.

## Что уже подготовлено

- контент разнесён по модулям в `apps/web/lib/content/`;
- изображения пространства и команды лежат в `apps/web/public/images/`;
- есть реестр изображений в `apps/web/lib/content/media.ts`;
- пользовательские тексты централизованы и типизированы.

## Ближайший рабочий процесс

### 1. Контентный цикл

1. Владелец проекта присылает новые тексты и фото.
2. Контент проверяется на tone of voice и медицинские формулировки.
3. Фото подготавливаются в web-формат.
4. Обновляются только данные и медиа-реестр.
5. Локально проверяются desktop/mobile версии.
6. Изменения публикуются.

### 2. Кто что делает

- Владелец проекта: утверждает финальные тексты, фото, фактические данные.
- Контент/маркетинг: формулирует описания услуг и специалистов.
- Разработчик: вносит структурные изменения, проверяет адаптив, SEO и сборку.

## Что лучше сделать следующим этапом

### P1

- добавить `apps/web/public/images/services/` и реальные фото направлений;
- добавить реальные портреты специалистов;
- расширить `media.ts` до полного брендового image registry;
- вынести контент главной страницы в отдельный модуль `home.ts`.

### P2

- сделать отдельные SEO-поля для страниц;
- подготовить расширенные профили специалистов;
- подготовить FAQ / информационные блоки;
- добавить more structured content для раздела `О центре`.

### P3

- оценить необходимость headless CMS;
- если обновления станут регулярными, перевести данные из файловой структуры в CMS без полной переделки UI.

## Будущая CMS-миграция

Текущая структура уже готовит к этому переходу.

Лучший путь потом:

1. Сохранить те же сущности:
   - `services`
   - `specialists`
   - `contacts`
   - `media`
2. Подключить CMS только как источник данных.
3. Оставить текущие компоненты страницы почти без изменений.

## Что можно сделать уже сейчас

- собрать полный набор production-фотографий;
- подготовить реальные тексты по каждому специалисту;
- подготовить реальные описания всех услуг;
- решить, какие SEO-метаданные нужны для каждой страницы;
- зафиксировать единый процесс именования и подготовки фото.
